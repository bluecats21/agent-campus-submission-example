# 需求文档：企业知识问答 Agent

## 1. 用户与目标

### 目标用户
企业内部员工

### 核心目标
帮助员工快速、准确地找到制度或产品问题的可靠答案，并提供完整的引用溯源。

### 成功标准
- 回答必须基于检索到的文档，不可凭空生成
- 必须提供文档 ID 和原文片段作为引用
- 发现文档冲突时，必须明确列出冲突并请求确认，不可擅自选择
- 资料不足时，必须说明缺口，不可编造答案

## 2. 输入与输出

### 输入
- **问题**：用户的自然语言问题
- **对话历史**（可选）：多轮对话上下文
- **文档库**：带文档 ID、版本日期的合成 FAQ 或制度文档

### 输出
- **回答**：基于文档的答案
- **引用**：文档 ID + 原文片段
- **资料缺口**：未覆盖的信息点
- **任务状态**：已完成 / 需确认 / 资料不足 / 工具失败

## 3. 工具能力

### 文档检索工具 (search_documents)
- **输入**：查询关键词
- **输出**：匹配的文档 ID 列表 + 相关片段摘要
- **用途**：初步定位相关文档

### 片段读取工具 (read_document)
- **输入**：文档 ID
- **输出**：完整文档内容
- **用途**：获取完整上下文，验证细节

## 4. 动态决策要求（ReAct 循环）

Agent 必须实现以下决策循环：

```
思考(Thought) → 动作(Action) → 观察(Observation) → 思考 → ...
```

### 决策场景

| 场景 | 决策逻辑 |
|------|---------|
| 检索结果充分且无冲突 | 基于文档回答，附带引用 |
| 检索结果有冲突 | 列出冲突，请求用户确认适用制度 |
| 检索结果不足 | 补充检索或读取更多文档 |
| 问题超出资料范围 | 明确说明资料缺口，不编造答案 |
| 工具调用失败 | 报告失败状态，提供降级方案 |
| 上下文追问 | 结合历史对话理解当前问题 |

### 执行上限
- 最大工具调用次数：5 次
- 达到上限时返回"未完成"状态及已获取信息

## 5. 验收场景（必须覆盖）

### 场景 1：明确答案
- **输入**：有唯一明确答案的问题
- **预期**：直接回答 + 文档引用

### 场景 2：文档冲突
- **输入**：存在冲突文档的问题（如报销期限 D01=30天 vs D02=15天）
- **预期**：列出冲突 + 两份文档引用 + 请求确认

### 场景 3：资料外问题
- **输入**：文档库未覆盖的问题
- **预期**：说明资料缺口 + 不编造答案

### 场景 4：改写后的相似问题
- **输入**：语义相同但表述不同的问题
- **预期**：能正确检索并回答

### 场景 5：上下文追问
- **输入**：基于前一轮对话的追问
- **预期**：结合历史理解问题

### 场景 6：工具失败
- **输入**：模拟工具调用失败
- **预期**：报告失败状态 + 降级处理

## 6. 范围与限制

### 范围内
- 单轮和多轮问答
- 文档检索与引用
- 冲突识别与处理
- 工具失败降级

### 范围外（本次不实现）
- 图形界面
- 线上部署
- 多 Agent 协作
- 生产级 Runtime
- 真实企业文档接入

## 7. 核心审核点

| 审核项 | 标准 |
|--------|------|
| 引用准确性 | 回答必须被引用原文支持 |
| 冲突处理 | 发现冲突时不擅自选择答案 |
| 检索改进 | 结果不足时能主动补充检索 |
| 动态决策 | 体现 ReAct 循环，非固定分支 |
| 可复现性 | 提供运行命令和 Trace 记录 |
